기존 ServletContextListener 구조를 최대한 그대로 유지하면서 문제를 해결하려면, **"브릿지(Bridge) 빈"**을 하나 추가하여 강제로 리스너를 호출해 주는 방식을 사용해야 합니다.
순수하게 web.xml에 등록된 리스너만으로는 Jira DC의 Hot Deployment 메커니즘상 원격 노드에서 이벤트가 발생하지 않는 한계를 넘을 수 없기 때문입니다.
따라서, 기존 코드는 거의 건드리지 않고, Spring이 리스너를 "대신 호출해 주는" 작은 어댑터를 추가하는 방식을 추천합니다.
해결 전략: "Spring Bridge" 패턴
 * 기존 리스너 유지: 로직이 들어있는 클래스는 그대로 둡니다.
 * 중복 실행 방지: 혹시라도 리스너와 Spring이 동시에 실행될 경우를 대비해 static 플래그로 한 번만 실행되게 막습니다.
 * 브릿지 빈(Bridge Bean) 추가: 모든 노드에서 확실히 실행되는 Spring Bean을 하나 만들어서, 거기서 기존 리스너의 contextInitialized 메서드를 수동으로 호출합니다.
구현 코드
1. 기존 서블릿 리스너 수정 (중복 방지 추가)
기존 클래스에 static AtomicBoolean을 추가하여 로직이 두 번 실행되는 것을 방지합니다. (배포한 노드에서는 서블릿 컨테이너와 브릿지가 둘 다 호출할 수도 있기 때문입니다.)
import javax.servlet.ServletContextListener;
import javax.servlet.ServletContextEvent;
import java.util.concurrent.atomic.AtomicBoolean;

public class MyExistingListener implements ServletContextListener {

    // 중복 실행 방지를 위한 정적 플래그
    private static final AtomicBoolean isInitialized = new AtomicBoolean(false);

    @Override
    public void contextInitialized(ServletContextEvent sce) {
        // 이미 실행되었다면 패스 (Thread-safe)
        if (isInitialized.getAndSet(true)) {
            return; 
        }

        // --- [기존에 구현하신 비즈니스 로직] ---
        System.out.println(">>> MyExistingListener 로직이 실행되었습니다.");
        
        // ServletContext가 필요하다면 sce.getServletContext() 사용
        // ...
    }

    @Override
    public void contextDestroyed(ServletContextEvent sce) {
        isInitialized.set(false); // 재배포 시 다시 실행되도록 초기화
        // 리소스 정리 로직
    }
}

2. 새로운 브릿지(Bridge) Bean 추가 (핵심)
이 클래스는 Spring에 의해 모든 노드에서 무조건 실행되며, 실행되자마자 위의 리스너를 수동으로 깨웁니다.
import org.springframework.beans.factory.InitializingBean;
import org.springframework.stereotype.Component;
import org.springframework.web.context.ServletContextAware;
import javax.servlet.ServletContext;
import javax.servlet.ServletContextEvent;

@Component // 또는 @Named
public class ListenerBridge implements InitializingBean, ServletContextAware {

    private ServletContext servletContext;

    @Override
    public void setServletContext(ServletContext servletContext) {
        // Spring이 주입해주는 ServletContext 저장
        this.servletContext = servletContext;
    }

    @Override
    public void afterPropertiesSet() throws Exception {
        // 이 메서드는 모든 노드에서 플러그인 로드 시 실행됨
        
        // 1. 기존 리스너 인스턴스 생성
        MyExistingListener listener = new MyExistingListener();
        
        // 2. 가짜(혹은 실제) 이벤트 객체 생성
        ServletContextEvent event = new ServletContextEvent(this.servletContext);
        
        // 3. 강제로 리스너 호출 (만약 이미 실행됐다면 내부 flag 때문에 무시됨)
        listener.contextInitialized(event);
    }
}

동작 원리
 * Node A (배포한 노드):
   * Jira가 web.xml을 읽고 MyExistingListener.contextInitialized()를 호출합니다. -> 실행됨 (Flag = true)
   * Spring이 ListenerBridge를 생성하고 afterPropertiesSet()을 호출합니다.
   * Bridge가 다시 MyExistingListener.contextInitialized()를 호출하지만, Flag가 true이므로 무시됨.
   * 결과: 1회 정상 실행
 * Node B (원격 노드):
   * Hot Deployment로 파일이 동기화되지만, Tomcat이 web.xml 리스너 이벤트를 발생시키지 않습니다. (Jira DC 특성)
   * 하지만 OSGi 컨테이너가 Spring Context를 로드하므로 ListenerBridge는 실행됩니다.
   * Bridge가 MyExistingListener.contextInitialized()를 수동으로 호출합니다. -> 실행됨 (Flag = true)
   * 결과: 1회 정상 실행
요약
> 기존 코드를 갈아엎지 않고, static 플래그 한 줄과 작은 브릿지 클래스 하나만 추가하면 됩니다. 이 방법이 기존 서블릿 기반 로직을 유지하면서 DC 환경을 지원하는 가장 안전한 우회로입니다.
